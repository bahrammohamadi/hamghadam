# سرور اختیاری و ایجنت — اسکلت آمادهٔ استقرار (۰.۸.۰‑پیش‌نمایش)

> **جایگاه:** ادامهٔ [`docs/11`](11-audit-and-gap-matrix.fa.md) — ردیف‌های `P4.2` و `P5.2` در نقشهٔ راه.
> **اصل حاکم:** محصول آفلاین‌اول است. این سرور **اختیاری** است و نبودش هیچ‌کدام از قابلیت‌های کار/تقویم/یادآور را نمی‌شکند.
> **وضعیت واقعی:** کد و اسکیمای سرور **نوشته و آزمون شده‌اند** (۲۱ تست Node، بدون خطا) اما **مستقر نشده‌اند** — استقرار نیازمند حساب Supabase/Vercel و کلید است.

## ۱) چه چیزی ساخته شد

| بخش | مسیر | وضعیت |
|---|---|---|
| API سرورلس (Vercel، Node ESM، بدون وابستگی) | `services/api/` | نوشته و تست شده؛ مستقر نشده |
| `GET /api/health` | `services/api/api/health.js` | سالم؛ فقط بولین «چه چیزی تنظیم شده»، بدون افشای مقدار |
| `POST /api/agent` | `services/api/api/agent.js` | احراز هویت Supabase + محدودیت نرخ + پیشنهاد ابزار + حسابرسی |
| قرارداد ابزارها و اعتبارسنجی آرگومان‌ها | `services/api/lib/agent.js` | ۷ ابزار، ۹ نوع فیلد، سقف طول، حذف فیلد ناشناس |
| اسکیمای Postgres/Supabase + RLS | `services/supabase/migrations/0001_init.sql` | نوشته شده؛ **روی Postgres واقعی اجرا نشده** |
| تست‌ها | `services/api/test/*.test.js` | ۲۱ تست، ۰ شکست |

## ۲) سیاست رازها (مهم)

- هیچ توکنی در مخزن، در اسکریپت، در `vercel.json` یا در گفتگو **نوشته نمی‌شود**. تنها نام متغیرها در `.env.example` هست.
- توکن‌هایی که در چت فرستاده شوند «لو‌رفته» محسوب می‌شوند؛ حتی اگر استفاده نشوند باید در سرویس مبدأ **باطل و از نو ساخته شوند** (GitHub → Settings/Developer settings؛ Vercel → Tokens؛ Supabase → Access Tokens).
- مسیر امن برای دادن دسترسی در Arena: از پنل **Connectors** اپ Supabase و Vercel را وصل کنید؛ ابزارها بدون دیدن/نگه‌داشتن راز در گفتگو کار می‌کنند.
- کلیدهای `SUPABASE_SERVICE_ROLE_KEY` و `AI_API_KEY` فقط در Environment Variables پروژهٔ Vercel قرار می‌گیرند و **هرگز** وارد APK نمی‌شوند. (الزام PRD: «کلید AI داخل اپ نباشد».)

## ۳) قرارداد HTTP

### `GET /api/health`
بدون احراز هویت. نمونهٔ پاسخ:

```json
{ "status": "ok", "service": "hamghadam-api", "version": "0.2.0",
  "time": "2026-10-25T09:00:00.000Z",
  "capabilities": { "auth": true, "agent": false, "audit": true } }
```

### `POST /api/agent`

| ورودی | توضیح |
|---|---|
| هدر `Authorization: Bearer <access token سوپابیس>` | الزامی؛ با `/auth/v1/user` اعتبارسنجی می‌شود |
| `message` | ۱ تا ۴۰۰۰ نویسه |
| `locale` | `fa` (پیش‌فرض) یا `en` |
| `tasks` | حداکثر ۵۰ مورد `{id,title,dueAt,status,starred}` — فقط همین فیلدها عبور می‌کنند |

| خروجی | توضیح |
|---|---|
| `reply` | پاسخ کوتاه مدل (حداکثر ۲۰۰۰ نویسه) |
| `actions[]` | `{tool, args, sensitive, requiresConfirmation:true, droppedFields}` |
| `rejected[]` | پیشنهادهای ردشده با دلیل: `unknown_tool` / `invalid_arguments_json` / `missing_or_invalid_arguments` |
| `model`, `latencyMs` | برای شفافیت و عیب‌یابی |

خطاها: `400` بدنه/پیام نامعتبر · `401` توکن · `403` مبدأ مرورگری غیرمجاز · `413` بدنه/پیام بزرگ · `429` نرخ · `502` خطای ارائه‌دهنده · `503` تنظیم‌نشده (`auth_not_configured` / `ai_not_configured`).

## ۴) قرارداد ابزارها

مدل فقط **پیشنهاد** می‌دهد؛ اجرا در دستگاه انجام می‌شود.

| ابزار | فیلدهای الزامی | حساس (هشدار صریح در UI) |
|---|---|---|
| `task.create` | `title` | — |
| `task.update` | `id` | ✔ |
| `task.complete` | `id` | ✔ |
| `task.delete` | `id` | ✔ (برگشت‌ناپذیر) |
| `event.create` | `title`, `startAt` | ✔ |
| `reminder.schedule` | `taskId`, `at` | ✔ |
| `notification.schedule` | `title`, `at` | ✔ |

هر ابزار یک اسکیمای بسته دارد (`additionalProperties: false`)، فیلد ناشناس پیش از رسیدن به دستگاه حذف می‌شود، متن‌ها بریده و لیست چک‌لیست به ۵۰ مورد محدود می‌شود. تاریخ‌ها فقط ISO‑۸۶۰۱ پذیرفته می‌شوند («فردا» رد می‌شود). حداکثر ۸ اقدام در هر پاسخ.

## ۵) مدل دادهٔ سرور

| جدول | نقش |
|---|---|
| `profiles` | یک ردیف به ازای هر کاربر؛ زبان/منطقهٔ زمانی |
| `devices` | هر نصب اپ؛ پایهٔ نشانگر همگام‌سازی آینده |
| `tasks` | آینهٔ سروری کارها؛ `deleted_at` برای حذف نرم، `idempotency_key` یکتا برای جلوگیری از تکرار در retry |
| `agent_runs` | حسابرسی: **هش‌دیجست SHA‑256** پیام، نام ابزارها، تعداد؛ متن خام ذخیره نمی‌شود |

قواعد: همهٔ زمان‌ها `timestamptz` (UTC روی سیم) · RLS روی هر چهار جدول با `auth.uid()` · `agent_runs` برای نقش‌های `anon`/`authenticated` کاملاً بسته است و فقط `service_role` می‌نویسد · هیچ حذف فیزیکی از سمت کلاینت مجاز نیست.

## ۶) جریان «پیش‌نمایش → تأیید → اجرا → گزارش نتیجهٔ واقعی»

1. کاربر در اپ (اختیاری) پیام می‌نویسد و صریحاً اجازهٔ ارسال بافت می‌دهد.
2. اپ `POST /api/agent` می‌زند؛ سرور فقط `actions` برمی‌گرداند.
3. اپ پیش‌نمایش می‌سازد؛ برای ابزارهای حساس هشدار «برگشت‌ناپذیر» نشان می‌دهد.
4. با تأیید کاربر، ابزار **روی Room محلی** اجرا می‌شود (نه روی سرور).
5. نتیجهٔ واقعی (شناسهٔ کار ساخته‌شده، تعداد تغییر‌یافته) در تاریخچهٔ قابل مشاهده ثبت می‌شود؛ لغو پیش از اجرا همیشه ممکن است.

این طراحی سه تضمین PRD را همزمان نگه می‌دارد: اجرای واقعی ابزارها، عدم وابستگی هسته به شبکه، و عدم انجام کار حساس بدون تأیید.

## ۷) استقرار

### مسیر A — از طریق Arena (بدون دیدن راز)
1. در پنل، Connectors → **Supabase** و **Vercel** را وصل کنید.
2. من اسکیما را روی پروژه اعمال، متغیرها را تنظیم و دو فایل `api/` را مستقر می‌کنم.
3. سپس `GET /api/health` باید `{"status":"ok"}` بدهد.

### مسیر B — خودتان با CLI
```bash
# 1) پایگاه داده
cd hamghadam-source/services/supabase
npx supabase link --project-ref <PROJECT_REF>
npx supabase db push

# 2) API
cd ../api
npx vercel link
npx vercel env add SUPABASE_URL production          # https://<ref>.supabase.co
npx vercel env add SUPABASE_ANON_KEY production      # کلید عمومی (anon)
npx vercel env add SUPABASE_SERVICE_ROLE_KEY production
npx vercel env add AI_BASE_URL production            # https://api.openai.com/v1
npx vercel env add AI_MODEL production
npx vercel env add AI_API_KEY production
npx vercel deploy --prod

# 3) آزمون دودی
curl -s https://<deployment>/api/health
```

مقادیر Supabase از داشبورد → Project Settings → API گرفته می‌شوند. هر ارائه‌دهندهٔ سازگار با OpenAI (OpenAI، OpenRouter، Groq و…) با `AI_BASE_URL` + `AI_MODEL` کار می‌کند.

## ۸) آزمون‌های اجراشده (واقعی)

```bash
cd hamghadam-source/services/api && npm test
```

- ۲۱ تست در ۳ فایل: `health`, `agent`, `agent-lib` — همه سبز، بدون شبکه (هر فراخوانی با `fetchImpl` جعلی انجام می‌شود).
- پوشش: ۴۰۱ بدون توکن · ۵۰۳ وقتی احراز هویت تنظیم نشده · ۴۰۳ برای مبدأ مرورگری · ۵۰۳ بدون کلید AI · مسیر موفق با دو پیشنهاد و یک ردشده · ۴۱۳ برای پیام بلند · حسابرسی بدون متن خام · ۴۲۹ با `Retry-After` · ۵۰۲ ایمن بدون نشت پیام ارائه‌دهنده · ۴۰۵ برای متد نادرست.
- `vercel.json` فقط سرصفحه‌های امنیتی و `maxDuration` است؛ هیچ مسیر محرمانه‌ای در آن نیست.

## ۹) آنچه انجام نشده / ریسک‌ها (صادقانه)

1. **استقرار انجام نشده است.** هیچ حساب، پروژه یا کلیدی در این مرحله استفاده نشد؛ بنابراین هیچ آدرسی برای آزمون واقعی وجود ندارد.
2. **SQL روی Postgres واقعی اجرا نشده**؛ فقط بازبینی دستی + آزمون‌های JS. پیش از انتشار، `supabase db push` روی پروژهٔ آزمایشی و سپس آزمون RLS (دو کاربر، تلاش برای خواندن ردیف دیگری) الزامی است.
3. **کلاینت اندروید هنوز به این API وصل نیست** (P5.1/P5.2 باز است). بدون صفحهٔ «دستیار» و بدون لایهٔ اجرای ابزارها، این سرور فقط آماده است.
4. **محدودیت نرخ در حافظهٔ هر نمونه** است؛ در مقیاس چند نمونه‌ای باید به Upstash/Redis یا جدول شمارش منتقل شود.
5. **بدون streaming** و بدون ابزارهای خواندنی (`task.list`, `calendar.query`) — عمداً، تا سطح حمله کوچک بماند.
6. **هزینه:** لایهٔ رایگان Vercel/Supabase برای مصرف کم کافی است؛ هزینهٔ واقعی، توکن مدل است و بدون سقف مصرف در داشبورد ارائه‌دهنده نباید روشن شود.

## ۱۰) گام بعدی پیشنهادی

1. استقرار روی پروژهٔ آزمایشی + آزمون RLS و `curl /api/agent` با توکن واقعی.
2. صفحهٔ «دستیار» در اپ (فقط با اتصال اختیاری) + مجری ابزار محلی + پیش‌نمایش/تأیید/لغو.
3. سپس — و فقط اگر لازم شد — فاز همگام‌سازی (outbox + cursor) روی جدول `tasks`.
