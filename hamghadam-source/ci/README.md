# ساخت خودکار APK (GitHub Actions)

خبر خوب: کل workflow آماده است و فقط **یک قدم دستی ۳۰ ثانیه‌ای** لازم دارد؛ بعد از آن هر بار که کد روی شاخه عوض شود، APK خودکار ساخته می‌شود.

## چرا این یک قدم دستی مانده؟

GitHub اجازه نمی‌دهد هیچ ابزار/اپی (و نه توکن) فایلی داخل مسیر `.github/workflows/` بسازد، مگر اینکه صریحاً مجوز **Workflows** داشته باشد. توکن اتوماسیون این مخزن این مجوز را ندارد و توکن شخصی هم در محیط اجرای خودکار قابل استفاده نیست (اعتبارنامه‌ها در مسیر خروج بازنویسی می‌شوند). بنابراین تنها راه، commit از رابط وب گیت‌هاب است.

## قدم دستی (انتخاب یکی از دو روش)

### روش ۱ — یک کلیک (محتوای فایل از قبل پر شده)

فایل [`one-click-link.txt`](one-click-link.txt) شامل یک لینک است که GitHub را روی صفحهٔ «ساخت فایل جدید» در مسیر `.github/workflows/android-apk.yml` با **محتوای از پیش پر شده** باز می‌کند. فقط:

1. لینک را باز کن.
2. پایین صفحه **Commit changes** را بزن (شاخه را عوض نکن؛ باید `arena/1911fde2-hamghadam` بماند).

### روش ۲ — کپی/پیست دستی (مطمئن‌ترین)

1. لینک [`one-click-link-short.txt`](one-click-link-short.txt) را باز کن (نام فایل از قبل پر است، محتوا خالی است).
2. در تب دیگر همین فایل [`android-apk.yml`](android-apk.yml) را باز کن، دکمهٔ **Raw** را بزن و همهٔ محتوا را کپی کن.
3. در تب اول، محتوا را جای‌گذاری کن و **Commit changes** را بزن.

بعد از commit، در تب **Actions** کارگاه **Build Android APK** خودکار شروع می‌شود (چون روی pull request همین شاخه trigger دارد). می‌توانی دستی هم **Run workflow** بزنی.

## بعد از اجرا

- اگر موفق شد: در پایین صفحهٔ اجرا، بخش **Artifacts** → `hamghadam-debug-apk` را دانلود کن. داخلش `app-debug.apk` است.
- اگر شکست خورد: artifact با نام `build-reports` شامل لاگ تست‌ها و گزارش‌ها است. لاگ را بفرست تا درستش کنم؛ من هم می‌توانم اجراها را از API بخوانم و خرابی‌ها را مرحله‌به‌مرحله رفع کنم.

## نکته‌ها

- خروجی یک APK **debug** است، نه نسخهٔ امضاشدهٔ انتشار.
- برای نصب روی گوشی، اجازهٔ «نصب از منبع نامعتبر» لازم است.
- workflow قبل از ساخت APK تست‌های JVM را اجرا می‌کند (`:app:testDebugUnitTest`).
- مسیر پروژهٔ اندروید `hamghadam-source/apps/android` است. اگر ساختار پوشه‌ها عوض شد، `working-directory` را هم به‌روز کن.
- پروژه Gradle wrapper ندارد؛ workflow نسخهٔ Gradle 8.9 را خودش نصب می‌کند (`gradle/actions/setup-gradle`). اگر می‌خواهی محلی با `./gradlew` بسازی، یک بار در Android Studio گزینهٔ «Generate Gradle Wrapper» را بزن.
