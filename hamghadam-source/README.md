# هم‌قدم — برنامه‌ریز کار و زندگی فارسی (نام موقت)

اپ اندروید **آفلاین و فارسی‌محور** برای ثبت سریع کارها، موعد، یادآور محلی، تقویم شمسی و عادت‌های روزانه.
این مخزن هم اسناد محصول/معماری را دارد و هم یک اپ اندروید واقعی و قابل‌ساخت (Kotlin + Jetpack Compose + Room).

> وضعیت: نسخهٔ `0.3.0` — «برش عمودی تک‌کاربرهٔ آفلاین». همگام‌سازی چنددستگاهی، ورود/OTP، پرداخت و AI **پیاده‌سازی نشده‌اند**.
> جزئیات صادقانهٔ آنچه آزموده شده و آنچه آزموده نشده در بخش [اعتبارسنجی](#اعتبارسنجی-و-محدودیتهای-فعلی) آمده است.

## قابلیت‌های این نسخه

| قابلیت | توضیح |
|---|---|
| تقویم شمسی دقیق | تبدیل دوطرفهٔ جلالی↔میلادی با الگوریتم چرخهٔ ۳۳ساله، تاریخ همه‌روزه، طول ماه و سال کبیسه |
| ثبت سریع فارسی | «فردا ساعت ۹ صبح جلسه با تیم !!» → عنوان + تاریخ + ساعت + اهمیت، کاملاً آفلاین و قابل توضیح |
| کارها | افزودن/ویرایش/انجام/حذف با واگرد، یادداشت، لیست، اهمیت، جست‌وجو، فیلتر |
| موعد و ساعت | موعد تمام‌روز یا ساعت‌دار، ذخیره به‌صورت روز مطلق + دقیقه، مستقل از تغییر منطقهٔ زمانی |
| تکرار | روزانه/هفتگی/ماهانه با سیاست «آخرین روز ماه» برای ماه‌های کوتاه |
| یادآور محلی | AlarmManager + اعلان با دکمهٔ «انجام شد»، زمان‌بندی مجدد پس از ری‌استارت |
| تقویم ماهانه | شبکهٔ شمسی شنبه‌محور، نشانگر روزهای دارای کار، انتخاب روز و افزودن کار برای همان روز |
| عادت‌ها | ثبت روزانه روی نوار هفته، زنجیرهٔ روزهای پیوسته، جلوگیری از ثبت روز آینده |
| ظاهر | تم روشن/تیره/سیستم، RTL کامل، ارقام فارسی قابل خاموش‌کردن، اعداد و تاریخ‌های فارسی |
| پشتیبان | خروجی/بازیابی JSON با اعتبارسنجی نسخهٔ فایل (بدون سرور) |

هیچ اتصال شبکه‌ای در اپ وجود ندارد؛ داده‌ها فقط در Room روی همان دستگاه ذخیره می‌شوند.

## گرفتن APK

**آماده‌ترین راه:** از [صفحهٔ Releases](https://github.com/bahrammohamadi/hamghadam/releases/tag/debug-18) فایل `app-debug.apk` را دانلود کن (نسخهٔ 0.3.0، ساخته‌شده از `main`؛ حداقل اندروید 8.0). همین فایل در تب Actions هم به‌عنوان artifact با نام `hamghadam-debug-apk` هست.

هر push روی `main` یا هر PR یک بیلد تازه می‌سازد که پس از ساخته‌شدن APK با `aapt2` تأیید می‌شود (شناسهٔ بسته، وجود launcher، سالم بودن بسته) و بعد در Releases منتشر می‌شود.

سه مسیر ساخت:

1. **GitHub Actions (بدون نصب ابزار روی رایانه)** — workflow در `.github/workflows/android-apk.yml` روی هر push و PR اجرا می‌شود و فقط `ci/build.sh` را صدا می‌زند؛ تست‌ها، ساخت APK و انتشار Release خودکار انجام می‌شود. جزئیات در [`ci/README.md`](ci/README.md).
2. **Android Studio** — پوشهٔ `apps/android` را باز کن، JDK 17 و Android SDK 35 لازم است، سپس Run.
3. **خط فرمان** — با Gradle 8.9:
   ```bash
   cd apps/android
   gradle :app:testDebugUnitTest   # تست‌های JVM
   gradle :app:assembleDebug       # ساخت APK دیباگ
   ```
   فایل خروجی: `app/build/outputs/apk/debug/app-debug.apk`.

نصب APK دیباگ روی گوشی نیازمند اجازهٔ «نصب از منبع نامعتبر» است. این APK امضای انتشار ندارد.

## ساختار مخزن

```text
hamghadam-source/
├─ apps/android/                     اپ اندروید (Kotlin، Compose، Room)
│  └─ app/src/main/java/ir/hamghadam/app/
│     ├─ domain/                     منطق خالص و تست‌پذیر: تقویم جلالی، پارسر فارسی، تکرار، جست‌وجو
│     ├─ data/                       Room (کار/لیست/عادت/ثبت عادت)، مخزن، تنظیمات، کدک پشتیبان JSON
│     ├─ notify/                     زمان‌بندی یادآور، گیرندهٔ اعلان، بازسازی پس از ری‌استارت
│     └─ ui/                         Compose: امروز، کارها، تقویم، عادت‌ها، تنظیمات، ویرایشگر و انتخابگرها
├─ docs/                             اسناد محصول، معماری، نقشهٔ صفحات و یادداشت پیاده‌سازی
├─ ci/                               workflow آمادهٔ ساخت APK + راهنما
└─ services/api/openapi.yaml         قرارداد اولیهٔ API (فعلاً فقط قرارداد، بدون سرور)
```

معماری اپ: تک‌Activity + Compose، `AppViewModel` با `StateFlow`، Room به‌عنوان منبع حقیقت محلی، تزریق دستی وابستگی در `AppContainer`. لایهٔ `domain` هیچ وابستگی اندرویدی ندارد و روی JVM تست می‌شود.

## اعتبارسنجی و محدودیت‌های فعلی

**آنچه واقعاً اجرا و بررسی شده است:**

- **بیلد واقعی Gradle/Android روی GitHub Actions سبز است** (اجرای `40166923073`، ۳ دقیقه): `:app:testDebugUnitTest` و `:app:assembleDebug` هر دو موفق، APK دیباگ حدود ۹.۹ مگابایت ساخته و به‌صورت Release منتشر شد.
- کل لایهٔ `domain` و کدک پشتیبان با Kotlin/JVM کامپایل و اجرا شد؛ **۵۷ تست واحد JVM** در ۷ کلاس تست با موفقیت اجرا می‌شود (`JalaliDate`, `PersianText`, `PersianCalendar`, `QuickAddParser`, `RepeatRule`, `TaskQuery`, `BackupCodec`).
- تبدیل تاریخ جلالی با پیاده‌سازی مرجع `jdatetime` برای **هر ۱۰۹٬۹۳۸ روز بین ۱۸۵۰ تا ۲۱۵۰** مقایسه شد: صفر اختلاف، صفر خطای رفت‌وبرگشت.
- کل کد اپ (شامل Compose، Room، AlarmManager و ViewModel) در این محیط با یک «آینهٔ stub» از APIهای اندروید/Compose از نظر **نوع و امضا** بررسی شد؛ خطای نحوی/امضایی باقی نمانده است.

**آنچه هنوز واقعاً آزموده نشده است:**

- ساخت کامل Gradle/Android (AAPT2، kapt/Room، R8، نصب روی دستگاه) در این محیط انجام نشده، چون Android SDK و مخازن Maven قابل دسترسی نبودند. اولین بیلد واقعی روی CI یا Android Studio انجام می‌شود؛ احتمال خطاهای جزئی در تنظیمات Gradle یا APIهای کمتر‌استفاده‌شدهٔ Compose وجود دارد.
- هیچ تست instrumented/UI یا اجرای روی دستگاه انجام نشده است.
- همگام‌سازی سرور، احراز هویت، پرداخت، AI، OCR/صوت، ویجت و نسخهٔ امضاشدهٔ انتشار پیاده‌سازی نشده‌اند.

## گام‌های بعدی پیشنهادی

1. اجرای workflow و رفع خطاهای احتمالی بیلد؛ سپس افزودن تست instrumented برای ثبت سریع و یادآور.
2. لایهٔ همگام‌سازی: صف outbox پایدار + قرارداد `POST /v1/sync/operations` (اسکلت در `docs/02` طراحی شده).
3. مناسبت‌ها/تعطیلات با feed نسخه‌بندی‌شده، ویجت صفحهٔ اصلی، جست‌وجوی سراسری، زیرکار و برچسب.
4. آماده‌سازی انتشار: امضای AAB، سیاست حریم خصوصی، سنجش crash-free، دسترس‌پذیری (TalkBack/کنتراست).
